# 换电脑 / 新机器部署说明

> 适用：把整个「餐厅系统」文件夹压缩打包，转移到一台全新的 Windows 电脑上继续正常使用。
> 适用版本：含 `server/` 本地数据库服务（v1.7.0 起）。
> 配套工具：根目录 `自检.bat`（环境自检）、`启动系统.bat`（启动并自动打开浏览器）。

---

## 0. 先搞懂两件事

**数据在哪**：全部业务数据在 `data\餐厅系统.db`（单个 SQLite 文件）。浏览器 localStorage 只是离线兜底副本，**拷走这个 .db 就等于拷走全部数据**。

**程序在哪**：`server\` + 根目录的三个 HTML。服务端只用 Python 标准库，**不需要 pip 装任何东西**。

因此移植 = 装 Python + 拷 `.db` + 拷 `server\` + 起服务。

---

## 1. 旧电脑上：打包前必须做

1. **冲干净离线数据**：双击 `启动系统.bat` → 打开 `熊猫五福餐厅进销存系统_真实数据版.html` → 确认右上角状态灯是 🟢「已同步 · revN」，且没有「N 次改动待同步」字样。
   浏览器里若还压着未回传的改动，这一步不做，那些数据就留在旧电脑里了。
2. **导出 JSON 兜底**：设置页 → `导出全部数据(JSON)`，另存一份到打包外的位置。
3. **记下版本号**：bat 窗口里会打印 `当前版本: rev=NNN`，抄下来（第 4 节验证时用）。
4. **关掉服务窗口**，让 `.db` 文件解除占用后再压缩。

---

## 2. 打包清单

### 必须包含

| 路径 | 用途 |
|---|---|
| `启动系统.bat`、`自检.bat` | 启动 / 环境自检 |
| `server\app.py`、`db.py`、`merge.py`、`config.json` | 本地数据库服务 |
| `data\餐厅系统.db` | **全部业务数据** |
| `data\backups\` 里**最新一个** `.db` | 冷备份兜底（其余可不带） |
| `熊猫五福餐厅进销存系统_真实数据版.html` | 主系统页面 |
| `熊猫五福餐厅进销存系统.html`、`熊猫五福餐厅菜品保本测算 (1).html` | 历史版本 / 测算参考 |
| `订单\`、`询价清单\`、`规范\`、`docs\`、`待比价任务_*.json` | 业务单据与文档 |

### 建议排除（体积大且绑死旧机器）

- `比价脚本\chrome_profile\` —— Selenium 的浏览器用户目录，写死旧机器绝对路径、绑定本机 Edge 版本、内含登录态。**不要打包**，新电脑首次跑脚本重新扫码登录 1688 即可。
- `比价脚本\debug\` —— 调试截图。
- `比价脚本\_smoke_*.py`、`_grep*.py` —— 临时调试脚本，内含旧电脑桌面绝对路径。
- `__pycache__`、`*.pyc`。

> 若 `server\data\` 还在，它只是历史遗留的空壳目录，**不是**数据库所在位置（`config.json` 的 `db_path` 相对项目根解析），可以删掉以免误导。

## 3. 新电脑：环境准备

1. 安装 **Python 3.8 及以上**（[下载](https://www.python.org/downloads/)），安装时务必勾选 **Add Python to PATH**。
   装完在终端执行 `python --version` 验证。
2. 解压到**固定、路径不太长的目录**（建议 `D:\餐厅系统`）。**不要**放进 OneDrive / 坚果云等同步盘，会产生冲突副本。
3. 双击根目录 **`自检.bat`** —— 它会依次检查：Python 版本 → 核心文件完整性 → 数据库文件 → 服务端脚本语法 → 8765 端口占用。全部显示 `OK` 再继续。

---

## 4. 新电脑：启动与首次同步

1. 双击 **`启动系统.bat`**，保持窗口开着。服务会自动打开浏览器访问 `http://127.0.0.1:8765/`。
2. 页面会**自动从数据库拉取全部数据**（右上角状态灯应立刻变 🟢「已同步 · revN」）。
3. 逐个核对：**原料数 / 菜品数 / 进货单数 / 库存金额** 是否与旧电脑一致（不要只看"有数据"，要核对条数）。
4. 验证落盘：随手录一笔测试采购单 → 状态灯转绿 → 关闭服务 → 重开页面，数据仍在。

> **为什么可以直接拉？** v1.7.1 起 `startSync()` 增加了「全新客户端判定」（`isFreshClient()`）：本机 localStorage 既无数据也无 rev 时，直接以数据库为准落地，**不会**把 HTML 内置的示例种子数据合并进真实库。
> 若你移植的是**改动前**的旧版 HTML，请改用第五节的手工流程。

### 访问方式建议：统一用 http，不要混用

服务端已内置静态托管，`http://127.0.0.1:8765/` 与双击 HTML 都能用，但两者的 **localStorage 是互相隔离的**（浏览器按 origin 隔离）。
选定一种方式后请长期固定，避免"两处数据看起来不一样"的困惑。推荐前者：origin 固定、无 `file://` 的跨域限制，且 `config.json` 已设 `open_browser: true` 自动打开。

---

## 5. 手工流程（仅当使用旧版 HTML 时）

老版本打开页面会把种子数据 `first-merge` 进真实库。此时用快照自愈：

1. 记下服务启动时打印的 `rev=NNN`；
2. 打开页面（此时发生污染，rev 变 NNN+1）；
3. 设置页 → 快照列表 → **回滚 rev NNN**（库内容恢复干净）；
4. 点 **「以数据库为准」** → 浏览器端也变干净。

`put()` 在每次写入前后都留快照，所以第 3 步一定找得到干净版本；`data\backups\*_boot.db` 冷备份是第二道保险。

## 6. 比价脚本（可选）

- 装依赖：`cd 比价脚本` → `pip install -r requirements.txt`（pandas / openpyxl / requests / selenium / webdriver-manager）。
- **必须用 `运行比价-网页版.bat`**。`运行比价.bat` 走的是 onebound 接口引擎，`config.json` 里 `api_key` 为空会直接报错退出；要用它得先去 [onebound](https://www.onebound.cn/) 申请密钥并填入 `比价脚本\config.json`。
- Selenium 需要本机装有 Chrome 或 Edge，首次运行联网下载驱动；首次抓价需扫码登录 1688，登录态会保存在新建的 `chrome_profile\`。
- 脚本内部全部用 `os.path.dirname(__file__)` 相对定位，**没有**硬编码路径，移植无需改动。

## 7. 常见问题

| 现象 | 排查 |
|---|---|
| 状态灯灰色「离线模式」 | 服务窗口是否开着 → 设置页「服务地址」是否为 `http://127.0.0.1:8765` → 跑 `自检.bat` 看端口 |
| 启动报端口被占用 | 改 `server\config.json` 的 `port`（如 8766），或 `python server\app.py --port 8766` |
| bat 提示没有 Python | 重装并勾选 Add Python to PATH，或用 `py` 启动器 |
| `data\餐厅系统.db` 打不开 / 报损坏 | 用 `data\backups\` 里最新的 `_boot.db` 覆盖回去 |
| 数据条数不对 | 设置页 →「以数据库为准」强制拉库；仍不对则用第 2 步导出的 JSON 备份恢复 |
| 中文乱码 | 两个 bat 都已 `chcp 65001`，若仍乱码检查终端字体与系统区域设置 |

---

## 8. 长期建议

- 每天第一次用完顺手做一次冷备份：设置页 → `导出全部数据(JSON)`，或直接复制 `data\餐厅系统.db`。
- 两台机器长期切换使用，可参考 `server\README.md` 第 3 节的「网盘同步」方案，注意把两台的 `machine_id` 改成不同值（`SHOP` / `HOME`）。
