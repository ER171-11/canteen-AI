## 1. 机读状态源（唯一权威链）

```
docs/迁移基线/FP-*.md            ← 唯一权威：每个 FP 一行，行尾状态标记
        │  scripts/gen-debt-table.ps1
        ├─► docs/迁移基线/欠账总表.md          （生成物，勿手改）
        ├─► docs/迁移颗粒度规范.md 附录 A       （生成物，勿手改）
        │  scripts/gen-progress-board.js
        └─► docs/进度看板.html                 （生成物，勿手改）
```

| 层级 | 文件 | 维护方式 |
| --- | --- | --- |
| 权威 | `docs/迁移基线/FP-<页面>.md` | 人工维护**行标注**；页面底部的「## 汇总」由脚本校验，不一致即报警 |
| 派生 | `docs/迁移基线/欠账总表.md` | 仅由 `gen-debt-table.ps1` 生成 |
| 派生 | `docs/迁移颗粒度规范.md` 附录 A | 同上 |
| 派生 | `docs/进度看板.html` | 仅由 `gen-progress-board.js` 生成 |
| 权威 | `docs/下一步任务清单_<日期>.md` | 人工维护：标题里的 `✅ 已完成`、§7 复选框、§7.1 表格 |
| 权威 | `docs/decisions/ADR-*.md` | 人工维护，顶部元信息表的 `状态` 行 |

**纪律**：任何派生文件都不得手工编辑；两处数字对不上时，看板会红条告警，而不是取平均值。

## 3. 门禁矩阵

| 门禁 | 命令 | 何时跑 | 失败说明什么 |
| --- | --- | --- | --- |
| 基线漂移 | `powershell -File scripts/gen-debt-table.ps1 -Check` | 每次改基线行或欠账卡后 | 欠账总表或规范附录 A 与基线行不一致，必须先重生成再提交 |
| 类型检查 | `cd apps/admin-web && npx tsc --noEmit` | 每次改前端 | 类型错误 |
| 前端构建 | `cd apps/admin-web && npm run build` | 每次改前端 | 构建失败 |
| BFF 测试 | `cd bff && npm test` | 每次改后端 | 算法平价/契约失败 |
| 红线守卫 | `ci/redline_guard.sh`（CI）/ `ci/redline_guard.ps1`（本机） | 每次改算法或直写相关代码 | 触犯业务红线 |
| CI | `.github/workflows/ci.yml` | 推送后 | 见第 5 节「CI 真实状态」 |

> **未验证 ≠ 通过。** 看板对没跑过的门禁一律显示「未验证」，不显示「通过」。

## 4. 变更纪律：改一个功能点的标准动作

1. 读 `docs/迁移基线/FP-<页面>.md` 中该行的**旧版证据**（旧 HTML 的 `文件:行号`），确认真实行为；
2. 改代码，遵守 `docs/下一步任务清单_*.md` §4 的业务红线与流程红线；
3. 同步改基线行的状态标记与「新版现状」；
4. 若该页面底部有「## 汇总」，同步改汇总（否则 `-Check` 会报漂移）；
5. `powershell -File scripts/gen-debt-table.ps1` 重生成总表与规范附录 A；
6. `powershell -File scripts/gen-debt-table.ps1 -Check` 确认无漂移；
7. `node scripts/gen-progress-board.js` 刷新看板；
8. 输出 `[WORK_DIFF]` 并更新 `store-inventory/docs/CHANGELOG.md`。

> 改了被基线引用的文件（如 `InboundPage.tsx`）后，**必须复核该文件在基线中的全部行号**——
> 行号一旦失效，基线就不再是可用证据。

`migrate_from_zip` 的纯函数差分与其余 7 个测试在 CI 真实执行。
本机已验证：模拟 CI 条件 = 8/9 + 1 显式 SKIP（exit 0）；真实基座 = 9/9（exit 0）。
