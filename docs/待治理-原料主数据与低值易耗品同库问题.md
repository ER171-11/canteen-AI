# 待治理：原料主数据与低值易耗品同库问题

> 状态：**现状记录 + 待讨论**，暂不落地方案。
> 起因：核对真实采购单导入时，发现系统里"食材原料"与"低值易耗品（耗材）"共用同一张 `ings` 表，
> 且现有分类字段已经半失控。本文先把情况说清楚，方案另议。
> 日期：2026-10-09

---

## 1. 一句话结论

`docs.data.ings` 既是**食材原料表**，又被迫承担**低值易耗品台账**的角色；
分类只靠一个自由文本字段 `cat`，既无"食材/耗材"区分，也无枚举约束，
导致库存、成本、损耗、比价、安全库存预警**都用同一套口径处理两类本质不同的东西**。

---

## 2. 现状（实测数据，主库 `store-inventory/data/餐厅系统.db`）

### 2.1 规模与分类分布


**① `其他` 类 19 项，全是食材，但本该各有归属**

其中「芹菜」属蔬菜类、「炮笋鱼/鲜鱿鱼」属水产类、「鲁花芝麻油/生抽」属干调类，全被丢进"其他"。

**③ 存在同名重复项**

「鲁花芝麻油 350ml」在 `ing` 列表中出现 **两次**（`findIng` 只做精确匹配，历史导入产生了重复条目）。

另 63 项为真实缺料（调料 37 / 生鲜 26），属主数据覆盖不足，不在本文讨论范围。

## 3. 问题清单（按严重度）

| # | 问题 | 具体表现 | 后果 |
|---|---|---|---|
| P1 | **无"食材/耗材"类型区分** | `ings` 只有 `cat` 一个粗分类，无 `type` | 耗材会进入所有食材口径的统计 |
| P2 | **分类字段无枚举约束** | `cat` 自由文本，历史值 7 种且互相重叠 | 报表分组不稳定，新增料默认 `其他` |
| P3 | **单位与换算语义被绕过** | `conv`（采购→库存换算）恒为 1；规格写进名称（`1件*24罐`、`5斤/包`、`30枚/板`） | 入库数量失真 → 库存、成本、损耗全错 |
| P4 | **无别名/同义词机制** | `findIng` 仅做名称精确相等（见 `import_orders_excel.js:632-645`） | 同物异名重复建料；「鲁花芝麻油350ml」已重复 |
| P5 | **耗材无对应属性** | 耗材没有"出成率 `yld`""配方消耗""安全库存 `safe`"的合理取值 | 字段被迫填默认值，语义污染 |
| P6 | **分类靠人工兜底** | 新料默认 `cat:'其他'`、`safe:0` | 安全库存预警与品类统计对这两类都不生效 |

## 4. 影响面（谁在消费 `ings`）

| 模块 | 位置 | 受影响点 |
|---|---|---|
| 库存台账 | `docs.data.ings[].stock`、库存流水 `logs` | 耗材与食材混在一张库存表，盘点口径不清 |
| 成本核算 | `bff/lib/recipe_cost.js`、配方 BOM | 若耗材被挂进 BOM，菜品成本被污染 |
| 损耗 | `bff/routes/loss.js`、`bff/lib/loss.js` | 损耗率分母含耗材，指标不可比 |
| 采购/比价 | `bff/routes/supply.js`、`bff/lib/supply.js`、`bff/lib/recv_import.js` | 比价按 `ing` 维度，耗材无多供应商比价意义 |
| 补货建议 | `bff/routes/inventory.js` `restock-suggest`、`bff/lib/algorithms/` | 耗材按"日均耗量×提前期"算补货，模型不适用 |
| 经营分析 | `bff/routes/analysis.js`、毛利率/损耗率报表 | 指标口径混入非食材 |

> 说明：以上为**风险面盘点**，未逐条实证；需要确认哪些报表确实会把耗材计入。

## 5. 现有机制梳理（改之前必须知道）

### 5.1 `ings` 字段（实测）

```
id, name, cat, unit, buy, conv, spec,
stock, avg, initStock, initAvg, initDate, last,
safe, yld, on, _u, safety, est, qty
```

- `unit` 库存单位 / `buy` 采购单位 / `conv` = 1 个采购单位折合多少库存单位
- `avg` 移动均价 · `last` 最近采购价 · `safe` 安全库存 · `yld` 出成率 · `on` 是否启用
- `safety / est / qty` 看起来是历史遗留或别名，需确认是否仍被读取

### 5.2 建料与匹配

```
findIng(db, name)        // 名称精确匹配（去掉【XX】前缀后再比一次）
createIng(db, name, unit) // 匹配不上就建：cat='其他', conv=1, safe=0, yld=1, on=true
```

位置：`bff/store-node/seed/import_orders_excel.js:632-672`

### 5.3 已知的相邻机制

- `recv_import.js`（验收导入）**没有**任何"非食材"过滤逻辑（已确认，0 处匹配）
- 全仓库搜索「耗材 / 物料 / 非食材 / 包材 / 劳保」仅出现在文档与 PRD，**代码层无实现**

## 6. 候选方案（待讨论，未选型）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **甲：加 `type` 字段** | `ings[].type = 'food' \| 'consumable'`，各口径按 type 分流 | 改动集中；兼容存量数据（默认 food） | 所有报表/算法需加过滤条件，遗漏一处就漏算 |
| **乙：独立 `consumables` 表** | 耗材单独建表 + 独立采购/库存链路 | 概念最干净，彻底不互相污染 | 改动最大：采购单、库存、供应商、报表双轨 |
| **丙：`cat` 增枚举"低值易耗"** | 只加一个分类值，靠分类过滤 | 最小改动，当天可落地 | 语义弱；与 `type` 相比无法阻止误入；报表仍同表 |
| **丁：采购单层面打标** | `recv.lines[]` 带 `type`，库存表不区分 | 不动物料主数据 | 库存仍混，只是能事后筛选 |

**倾向（仅供讨论）**：先落「甲 + 丙组合」——加 `type` 做**语义**分层，
同时把 `cat` 收敛为枚举（含"低值易耗"），报表口径统一按 `type` 过滤；
若后续耗材用量大、管理诉求变强，再演进到方案乙。

## 7. 待决策问题清单
