> 评估对象：**已交付闭环的 7 个模块**——M1 经营分析 / M2 排班员工 / M4 食安证照 / M8 设备能耗 / M9 财务税务 / M10 供应链 / M12 损耗报损

## 1. 背景与适用范围

### 1.1 目的

以食品安全标准体系为基准，逐条对照 7 个已交付模块的现有设计，回答三个问题：

1. 体系里哪些要求**现有模块已经承载**（可复用）；
2. 哪些要求是**缺口**（现有数据模型 / 接口 / 写回动作无从表达）；
3. 缺口应当**怎么补**（补字段优先、慎建新表），以及**优先级**。

供评审者判断改造范围、工作量与排期。本文不动代码；确认后再按第 6 节分期开工。

### 1.2 体系输入摘要

体系把奥运"全流程、可追溯、专人专责、零容忍"落地为社餐门店可执行规范，与本次评估强相关的控制域：

| 章 | 控制域 | 与代码强相关的可数据化要求 |
|---|---|---|
| 2 | 组织职责 | 三级架构（决策/专责/执行）、店长第一责任人、**日管控 / 周排查 / 月调度** |
| 3 | 260 项检测 | 四层检测（供应商合格证明 + **入场快检** + 重点批次送检 + 每餐留样）；重点食材检测项与频次；不合格处理 |
| 4 | 过敏原 | 八大类、**过敏原食材台账**、**菜品过敏原配方卡**、菜单/点单标注、交叉污染防控 |
| 5 | 五专 | 专人 / 专室 / 专工具 / 专冷藏 / 专消毒 + **专车（专用冷链配送）** |
| 6 | 分区标准 | 9 大分区（面点/板前/热菜/洗消/凉菜间/厕所/前厅/前台/收银）SOP |
| 7 | 执行细节 | 验货（索证/感官/快检/冷链/计量/台账）、出品（**中心温度 ≥70℃**、热菜 ≥60℃、凉菜 ≤8℃、≤2h）、留样（**≥125g / ≥48h**）、**九类台账**（留存 ≥2 年）、危机处理 |
| 8 | 应急预案 | 组织分工、事故分级、报告（**1h 内**）、半年演练 |
| 9 | 培训 | 内容体系、频次、考核 **80 分**、档案 ≥2 年 |
| 10 | 岗位方案 | 9 岗位职责卡片 |
| 11 | 监督考核 | 日常自查（附录 F）、检查奖惩、持续改进 |
| 附 A–G | 台账模板 | 进货查验 / **晨检** / 留样 / 消毒 / **冷藏冷冻温度** / 自查 / 培训 |

### 1.3 评估口径

对每个模块，按现有架构的**四层落点**逐一比对：

```
数据表（store-inventory/migrations/*.sql）
  → 纯逻辑（bff/lib/*.js）
    → 路由（bff/routes/*.js，GET 只读 / POST enqueue）
      → 写回动作（bff/lib/algorithms/registry.js 注册）
```

两条系统级红线贯穿全文，改造建议不得违反：

- **写回红线**：GET 只读，写操作一律 `enqueue` 进 `actions` 队列，经审批中心确认才落库（`bff/routes/foodsafe.js:17`、`bff/routes/actions.js`）。
- **高频数据红线**：`eq_temp`（温度时间序列）**不进 rev 体系**，只落本地 SQLite（`store-inventory/migrations/001_new_tables.sql:338-345`）。任何"高频温度采集"类改造都要沿用此边界。

### 1.4 术语

| 术语 | 含义 |
|---|---|
| 四层落点 | 上文"数据表 → 纯逻辑 → 路由 → 写回动作"的模块实现骨架 |
| 补字段优先 | 缺口尽量在既有表/接口上 `ADD COLUMN` 或扩展 payload，而非新建表 |
| 状态机 | 有明确生命周期与分级色调（绿/黄/红）的领域对象，如留样 48h、证照临期 |
| 单列立项 | 落不进 7 个已交付模块、需新增模块或对接外部系统的要求（见第 5 节） |

3. **C3 快检（新增轻表，不复用留样）**：建议 `fs_quicktest`（date/batch_no/ing_name/item/result/level/operator/ts）；动作 `fs.quicktest.log`；接入收货端（`recv.accept`）做"快检不合格 → 拒收"联动。→ 这是体系"入场快检"的落点。
4. **C4 送检**：`fs_trace` `ADD COLUMN report_no TEXT / report_file TEXT`（附件走对象存储）；或独立 `fs_labtest` 台账。→ 让溯源从"有没有证号"升级为"有报告可查"。
5. **C11 过敏原**：与菜谱/配方联动（见第 5.5 节），M4 只承载"过敏原食材台账"的**查询与标注**视图。
6. **iOS 补齐**：`FoodsafeView.swift` 目前仅骨架，与 Android 功能不对等（非食安体系新增要求，属既有欠账）。

### 4.1 九类台账统一化与留存 ≥2 年（C15）

### 4.2 日管控 / 周排查 / 月调度（C16）

- **现状**：无。
