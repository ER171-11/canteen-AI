## 一、测试口径与范围（先对齐，再执行）

### 1.1 测试分层（三重齐过才算「闭环」）

| 层级 | 判定方式 | 责任范围 |
|---|---|---|
| 页面级 | 逐模块肉眼走查入口 / 依赖数据 / 关键交互 / 验收点 | `任务卡执行清单.md` §9.1–9.7 |
| 脚本级 | 模块 e2e 断言 + 写回闭环 + 静态与红线全绿 | §三 各任务「断言」列 |
| 门禁级 | 官方 `进度看板.html` 的「门禁与 CI / 流程签收敞口」全绿且 4 项敞口关闭 | `GATE-*` 任务 |

### 1.2 测试范围边界

- **纳入**：后场 7 模块（M1/M2/M4/M8/M9/M10/M12）、前厅 5 模块接口预留（M3/M5/M6/M7/M11）、共享底座（S 系列）、既有进销存底座（9 页 106/151 功能点）。
- **不纳入**：前厅 5 模块的业务功能闭环、41 张欠账卡、iOS 原生 App 工程化（33 Swift View）。
- **测试性质**：第一版以「只读看店 + 写回经确认台落库」为验证主线，**不测前厅真实业务**，只测其「接口就绪 + 可切换」。

### 1.3 环境与红线约束（测试前置）

- 启动：双击根目录 `启动测试.cmd`（拉起 BFF:8787 + admin-web:5173），登录 `boss / wufu123`；若 BFF 为旧进程先关闭重跑再 `Ctrl+F5`。
- **降级信号**：任一页顶部黄条「后端 `/api/xxx` 未连通，当前为本地样例数据」= 未加载新路由**或**快照缺该模块数据 → 页面回退样例，**≠ 功能没生效**。
- **写操作红线**：所有「登记」只入队，须到「平台 → 审批中心」`confirm` 才落库；**页面弹 success ≠ 已写库**。
- **受保护逻辑**：`rebuildStock()` / `dishRecipeCost()` / `seedDB()` 全程零改动；用量换算只读 `calcQtyOf`；成本只读 `dishRecipeCost`。
- 隔离验证：e2e 脚本均使用独立 `BFF_DATA_DIR` + `BFF_PORT`，不污染真实数据。
