# 菜品配方 模块设计

## 1. 模块职责
维护菜品主数据(名称/类型/估算成本/售价)及配方(BOM)。已配配方的菜按原料实时成本核算；未配配方的使用保本测算估算成本(est)。

## 2. 核心流程图
```mermaid
flowchart TD
  A[菜品目录 RAW] --> B[菜品主数据 dishes]
  C[食谱卡净料用量] --> D[配方 BOM: rec[dishId]]
  D --> E[dishRecipeCost 按原料实时均价核算]
  B --> F{是否有配方?}
  F -- 是 --> E
  F -- 否 --> G[使用 est 估算成本]
  E & G --> H[菜品毛利率 = (售价-成本)/售价]
```

## 3. 数据模型 / 接口契约
- 数据结构:
  - `DB.dishes[]`: `{id, cat, name, est, price, q, on}`
  - `DB.rec`: `{[dishId]: [{ing, qty}]}` — 配方(净料用量)
- 成本核算:
  - 配方成本 = Σ(净料用量 ÷ 出成率 × 原料库存均价)
  - 估算成本 = `dish.est`（来自保本测算）
- 关键函数: `dishRecipeCost(did)`、`dishCost(d)`、`dishCostType(d)`、`recipeLines(did)`

### 3.1 字段 `q`（日均销量）的用途边界 —— 重要
- `q` 来自「保本测算」第5列，**仅供「结构测算」Tab 的只读测算使用**。
- `q` **不参与**任何业务计算：不参与配方成本、不参与销售出库扣减库存、不参与实际毛利核算。
- 本模块（菜品配方）的列表**不展示** `q`，也不允许在此页编辑 `q`。
- 修改 `q` 的唯一途径是重置/重建种子数据；测算页对 `q` 的调整仅存在于内存副本，页面刷新即复位。

## 4. 关键设计决策 (ADRs)
- 菜品目录86道来自「保本测算」，分类: 引流/爆品/利润/形象/常规
- 当前 RECIPES 为空（无真实食谱卡），所有菜品成本使用 est 估算值
- 配方按净料用量录入，系统自动除以出成率还原毛料消耗
- **配方管理与毛利测算隔离**（2026-09-12）：新增「结构测算」Tab 承载量本利模型，该页以只读方式消费菜品主数据，任何调价/调量/上下架均不写回 `DB.rec`/`DB.dishes`/库存。详见 [结构测算.md](./结构测算.md)

## 5. 已知限制与风险
- 无食谱卡时毛利率基于估算成本，仅供参考
- 配方中引用的原料若不存在，会跳过该行（需保证原料名称匹配）
- `q` 是为测算引入的模拟口径字段，与真实销售数据（`dishSalesAgg` 基于 `DB.sales`）互不干扰，两者不可混淆
- **口径澄清（2026-09-21）**：本页「近 N 天销量」= `dishSalesAgg(dish,N)`，条件是 `s.date >= daysAgo(N-1)`，
  即**近 N 天的销售总份数**；「结构测算」页切到真实口径时用的是**同一份数据除以 N 得日均**（`dishRealQty / N`）。
  因此两页的**总份数一致、口径同源**，但结构测算页展示的是「日均」列——这是量本利模型的输入要求，不是数据不一致

## 6. 受保护逻辑
- `dishRecipeCost()` 成本核算逻辑，禁止直接修改

## 7. 批量导入食谱卡（2026-09-13 新增）

- 入口：`#tab-dish` 工具条「📥 批量导入食谱卡」+「下载导入模板」，文件框 `#fileRecImport`
- 支持格式：`.csv`（Excel「另存为 CSV」，自动兼容 UTF-8 / GBK）、`.json`（`{recipes:[{dish,cat,lines:[{ingName,qty,unit}]}]}` 或 `{items:[{dish,ingName,qty}]}` 扁平列表）
- CSV 列：`菜品名称 / 菜品分类 / 原料名称 / 净料用量 / 库存单位 / 原料分类`（后三列可空；同一菜品多行即为多个原料）
- 流程：`readImportFile → parseRecInput → previewRecImport（预览确认）→ commitRecImport（写库）`
- **新原料自动入库（本需求核心）**：食谱卡中按名称未匹配到的原料，由 `createIngFromImport()` 新建到 `DB.ings`（`stock/avg=0`），因此一定会出现在「原料库存」中；待该原料被采购入库后，由 `rebuildStock()` 生成均价，`dishRecipeCost()` 随即按实时均价核算
- 菜品匹配：按名称精确匹配，未匹配到则 `createDishFromImport()` 新建（类型默认「常规」，`price/est/q=0`，可后续在菜品列表补齐）
- 同名菜已有配方时：默认**覆盖**（食谱卡视为完整定义），预览页可取消勾选改为「按原料合并用量」（同原料覆盖用量、新原料追加）
- 关键函数：`parseRecInput()`、`previewRecImport()`、`commitRecImport()`、`downloadRecTemplate()`
- 约束：**只**在 `commitRecImport()` 内写 `DB.rec`/`DB.dishes`/`DB.ings`；预览阶段不得写库；与「结构测算」只读层无关，不写 `SD`/`CALC_P`
- 未改动：手工「配/改配方」`openRecipe()` 一行未改

## 8. 菜名映射（别名管理，2026-09-21 新增）

> 外部平台（美团等）导出的菜名常与本店菜名不一致（如「招牌口水鸡(份)」「口水鸡 1份」），
> 导入销售数据时若匹配不上就无法参与库存扣减与毛利核算，因此需要一层**显式别名**。

- 数据：`DB.dishAlias`（`migrateV4()` 内软迁移，缺失按 `{}` 处理，**未升 `DB.v`、未动 `LS_KEY`**）。
  - 结构：`{[平台菜名]: {dish: 菜品id, mul: 份量系数}}`；`mul` 用于「平台上 1 份 = 本店 0.5 份」这类折算。
- 入口：销售页「🏷 菜名映射」→ `openAliasMap()`：列表 / 删除 / 新增。
- 自动记忆：导入预览里对「未匹配」项指定菜品后，`setDishAlias()` 自动记别名，下次导入同平台文件即自动命中。
- 匹配优先级（`matchSaleDish()`）：**别名 → 精确 → 归一化**（去空格 / 括号规格 / 标点）；**不做模糊包含**，避免误配导致错误扣库存。
- 关键函数：`openAliasMap` / `setDishAlias` / `matchSaleDish` / `normDishName`；详见 [销售收银.md](./销售收银.md) 第 6 节。
