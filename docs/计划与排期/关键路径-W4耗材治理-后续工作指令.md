## 1. 背景与目标

`docs.data.ings` 既是食材原料表、又被当成低值易耗品台账，分类只靠自由文本 `cat`，导致库存/成本/损耗/比价/安全库存五处口径把食材和耗材混算。

治理方案已定案（**甲 + 丙组合**）：加 `type` 字段做**语义**分层（`food` / `consumable`），同时把 `cat` 收敛为枚举。详见 `docs/待治理-原料主数据与低值易耗品同库问题.md`。

## 3. 关键事实澄清（新对话务必知道，避免走弯路）

1. **`ings` 是 `docs.data` 里的 JSON 数组，不是 SQLite 表**。`db.js`/`db.py` 的 SCHEMA 只有 `docs`、`snapshots` 两张表，业务数据整体存 `docs.data` JSON。
   → 待治理文档 §8 写的 `ALTER TABLE ings ADD COLUMN type TEXT ...` 是**过时/错误**的 DDL，**不要执行**。`type` 是 JSON 对象字段，已通过 `createIng` 写入，无需任何 DDL。
2. **`type` 与 `cat` 是正交两层**：
   - `type`（food/consumable）：机器判定，决定「进不进食材口径」（成本/损耗/比价/补货/经营分析）。
   - `cat`（品类）：人工维护，决定「展示在哪个分组」。
3. **`cat` 收敛枚举（已统一唯一标准）**（Android 商品目录 `apps/android-app/app/src/main/java/com/pandawufu/app/features/inventory/CatalogTab.kt` 的 `CAT_PRESETS`）：
   `干调类 / 肉类 / 蔬果 / 色源 / 面点 / 冷链 / 耗材包材 / 菜谱挂钩 / 其他`
   ✅ 命名已统一为「**耗材包材**」（待治理文档/看板/发版计划已同步）；「低值易耗」仅保留为会计科目「营业费用-低值易耗」（决策 #2），不是 `cat` 枚举值。
   ⚠️ 历史枚举与收敛枚举不一致，归位时需一并迁移：`蔬菜类→蔬果`、`鲜肉类→肉类`、`水产类→冷链`、`菜谱挂钩` 两项（黑猪前肩肉→肉类、香菇→蔬果）。均已列入归位工作单。
4. **历史数据无稳定 id 映射**，回灌/匹配按 `name`（`cleanName` 归一后精确匹配，`findIng` 还去【XX】前缀）。
5. **`isFood` 对 `type` 缺失的历史行返回 true**（按食材），所以 95 项历史行 `type` 字段虽缺失，口径过滤已正确，功能不受影响。
