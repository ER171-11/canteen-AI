# 迁移颗粒度规范（替代式迁移必须遵守）

> 制定日期：2026-09-28　适用范围：**任何「用新系统替代既有可用系统」的迁移**
> 触发背景：admin-web 的「进货入库」页被判定为已完成（页面存在、接口存在），
> 但对照旧系统截图发现约 12 项功能缺失（结算单、补付、批量导入、汇总卡等）。
> 根因：**以「页面/模块」为迁移与验收单位**，而页面级功能从未被清单化，导致静默丢失。
> 本规范的目标是让「功能丢失」在流程上**不可能静默发生**。

---

## 1. 迁移单位 = 功能点（FP）

**禁止**以「模块」「页面」「接口」为单位宣称迁移完成。最小迁移与验收单位是 **功能点（Feature Point）**。

**FP 的定义**：用户可见、可**单独操作**、可**单独验证**的一个动作或视图。
判据：能写成一句「用户可以 ____」，且能单独演示成功或失败。

- ✅ 正确粒度：`生成单张结算单 PDF`、`对某进货单补付`、`下载进货单导入模板`
- ❌ 错误粒度：`结算单模块`、`进货入库页`、`采购域接口`

**FP 编号规则**：`FP-{源页面标识}-{两位序号}`，如 `FP-RECV-04`。源页面标识取自源系统（RECV=进货入库、PO=采购管理、ING=原料库存…）。

## 2. 强制前置产物：《源系统功能清单》

替代式迁移**启动前**必须先产出源系统的 FP 清单（基线），并满足：

1. 每个 FP 带**来源证据**：`文件:行号` 或界面定位描述（不可只凭记忆）；
2. 清单由人工确认（可由 AI 从源码抽取，但必须人工复核）；
3. 清单文件置于 `docs/迁移基线/FP-{页面}.md`，并登记到本规范附录 A。

**无基线 → 不得启动迁移，更不得宣称完成。**

## 3. 四态处置（每行必填，留空即失败）

| 标记 | 状态 | 含义 | 附加要求（缺一不可） |
|---|---|---|---|
| ⬆️ | 已移植 | 新版有对应实现 | 填新版位置 + **验证方式**（命令/操作路径） |
| 🔄 | 等价替代 | 实现方式不同但**能力对等** | 填 **ADR 编号 + 批准人**；须能演示对等 |
| ⬜ | 待补 | 承认缺失，需要补 | 填**关联任务卡 ID** 与排期 |
| ⚰️ | 废弃 | 不再需要 | 填**业务理由 + 批准人** |

> **关键闸门**：不允许存在未标注状态的行。
> 「不知道有没有」「以后再说」在流程上不被允许——这正是上一次静默丢失的入口。

> **行号时效（T5 教训）**：旧版行号指向只读的旧 HTML，**永不变**；新版行号是**源码快照**，
> 会随后续改动整体漂移（T5 改 `InboundPage.tsx` 后，T4 登记的 6 处行号全部失准）。
> 因此：**任何改动被基线引用的源文件的任务，必须同步复核并修正该文件在基线中的全部新版行号**，
> 复核后在本页顶部注明「按 N 行版本全表复核」。**漂移的行号等于没有证据。**

## 4. 验收门禁

1. 某页面可宣称「迁移完成」的前提：该页 FP 清单中 **⬜ 数为 0**；若存在 ⬜，每个都必须有已批准的任务卡与负责人，且经负责人签字放行。
2. **禁止以「页面存在 / 接口存在」充当「功能完成」**——本次事故的直接原因。
3. **两条独立门禁，不可互相替代**：
   - **平价（差分）测试** → 证明「**算得对**」（数值口径、数据层忠实）
   - **FP 清单** → 证明「**功能齐**」（交互、输出、操作闭环）
   > 平价测试全绿**不等于**功能已迁移。二者必须分别通过。
4. 迁移收尾时，FP 清单归档为该页的验收记录，与 CHANGELOG 条目互链。

## 5. 自动化守卫（CI）

`ci/redline_guard.sh` **R14**：扫描 `docs/迁移基线/*.md`，凡 `| FP-` 开头的行必须带四态标记之一，
出现未标注行即 FAIL（详见该文件注释）。本机无 bash 时用 PowerShell 等价校验（见附录 B）。

## 6. 角色与节奏

| 阶段 | 动作 | 产出 |
|---|---|---|
| 迁移前 | 从源系统源码/界面抽取 FP 清单，人工复核 | `docs/迁移基线/FP-*.md`（全 ⬜ 起步） |
| 迁移中 | 每完成一个 FP，更新状态与验证方式 | 清单状态滚动更新 |
| 迁移后 | ⬜ 清零（或全部有批准排期）→ 归档 | 验收记录 + CHANGELOG 条目 |

## 7. 与既有协议的关系

- 本规范是 `store-inventory/docs/AGENTS.md` §7「替代式迁移协议」的展开版；
- 违反本规范属于 `AGENTS.md` §3 高风险操作，需输出 `[EDIT_PLAN]` 等待确认；
- 与 ADR-002（去 Python）配套：ADR-002 管**形态层怎么换**，本规范管**功能层不许丢**。

## 附录 B：本机（Windows / 无 bash）手工校验

```powershell
$bad = 0
Get-ChildItem docs\迁移基线\*.md | ForEach-Object {
  $rows = Get-Content $_.FullName -Encoding UTF8 | Where-Object { $_ -match '^\|\s*FP-' }
  $un   = $rows | Where-Object { $_ -notmatch '已移植|等价替代|待补|废弃' }
  if ($un) { $bad++; "FAIL $($_.Name) 未标注 $($un.Count) 行" } else { "OK $($_.Name) $($rows.Count) 行" }
}
if ($bad) { "== 迁移基线未通过 ==" } else { "== 迁移基线全部通过 ==" }
```
