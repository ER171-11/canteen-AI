# 菜品消耗闭环 · 完整实施方案（定稿 v2.0）

> 本文件为「菜谱配置 → 映射原料库存 → 承接外部菜品消耗 → 反馈原料库存 → 达阈值 → 采购建议 → 采购单 → 进货入库」闭环的定稿方案，
> 可作为新对话 craft 模式的 `[EDIT_PLAN]` 基线，也可作为验收对照。

## 一、业务目标

打通链路：**菜谱配置 → 映射原料库存 → 承接外部菜品消耗数据 → 反馈原料库存 → 达阈值 → 反馈采购管理 → 生成采购单 → 进货入库**。

## 二、已确认的决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 外部数据来源 | 美团点单统计，格式不确定 → 手工录入 + 文件导入双通道 |
| 2 | 是否带金额 | 大概率带 → 落 `DB.sales`，复用现有销售/毛利/库存链路 |
| 3 | 金额口径 | 给的是「用户实付/商家实收/两者都有」不确定 → 保留冗余、可事后重算 |

| 7 | 在途量 | 采购单数量不可靠 → 排除在库存之外，只在采购管理内部取数防重复下单 |

## 三、核心业务原则（硬规则）

1. **采购单不影响库存**：采购单（CG）只产生应付账款，不入库、不影响 `stock`/`avg`；库存只由「期初 + 进货单入库 − 销售出库 ± 盘点」决定。采购单数量仅在补货建议中作防重复下单参考，且只读取采购管理自身数据。
2. **进货单 → 采购单单向回流**：进货单可自愿关联采购单，回写收货状态；采购单不会反向生成或约束进货单。已收数量 `recvQty` 为派生值，每次启动全量重算，不采信远端值。
3. **自动生成 ≠ 自动下单**：补货建议可自动生成，但转正式采购单必须人工确认。
4. **金额口径可事后重算**：导入时保留原始金额明细 `srcAmt`。

## 四、数据模型变更（最小集，全部可选 + 读时兜底）

- **`DB.sales[]` 追加**：`src` / `srcNo`(幂等键) / `batch`(整批撤回) / `amtMode`(A/B/C/D) / `srcAmt`{list,paid,net,fee,promo} / `settled`。
- **`DB.dishAlias`**（新增）：`{ 外部菜名: { dish: 菜品ID, mul: 份量系数 } }`。
- **`DB.ings[]` 追加可选**：`sup` / `moq` / `pack` / `safe` / `yld`。
- **`DB.orders.lines[]` 追加可选**：`recvQty`(采购单位) / `st`(`closed`/`canceled`)。
- **`DB.recv[]` 追加可选**：`po`(关联采购单 id)。
- **`DB.plans[]`**（新增）：`{id,no:'BY'+日期,date,genAt,by,status,lines:[{ing,cur,safe,daily,onway,need,sug,unit,buy,conv,qty,price,supplier,st,po}]}`。
- **`DB.restock`**（新增）：`days` / `lead` / `gap` / `useOnway`。

软迁移守卫加在 `migrateV4()`：`dishAlias={}` / `plans=[]` / `restock={}`。

## 六、红线声明

- 全程不改写 `rebuildStock()` / `dishRecipeCost()` / `calcSaleCost()` / `seedDB()` 业务种子 / `LS_KEY`。
- 采购单绝不能进库存：`openOrderQty()` 只遍历 `DB.orders`。
- `recvQty` 派生值，落地不采信，必须靠 `syncOrderRecv()` 重算。
- 外部销售数据写入只允许在 `commitSaleImport()` 内，预览阶段禁止写库。
- 金额口径改动必须同步 `resolveSaleAmt()` 与 `openSaleAmtRecalc()` 两处。
- 结构测算改销量口径只改 `SD`，禁止写回 `DB.dishes.q`。
- 新增字段走「可选字段 + 读时兜底」软迁移，不升 `DB.v`、不动 `LS_KEY`。
- 真二进制 `.xls` 解析器改动需回归：中文 SST / SST 跨 CONTINUE / 空单元格多工作表。

## 七、验收验证清单

1. `.xlsx`/`.csv`/伪`.xls`/真二进制`.xls` 各导一次 → 预览正确、失败降级不拒收、重复拦截、整批删除库存回退。
2. 录已知配方菜 N 份 → 库存按 `N × 净料 ÷ 出成率` 扣减。
3. 结构测算切「近30天真实」→ 与配方页「近30天销量」一致；无销量仍显示估算兜底。
4. 库存压到安全线下 → 自动生成建议单；不确认则 `DB.orders` 无新增。
5. 建议单转采购单 → 收货生成关联进货单 → 库存回升 → 状态推进。
6. 双机同步冒烟；SQLite + localStorage 兜底正常。
