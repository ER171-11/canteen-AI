## 1. 替换 §1.2 技术栈选型

| 层 | v1.0（Python） | **v2.0 现状** | 说明 |
|---|---|---|---|
| 店内运行时 | Python 标准库 `http.server` + `sqlite3` | **Node** `bff/store-node/`（server/db/merge/consumer/pusher） | 零第三方依赖，`node:sqlite` |
| 业务算法 | `queue_consumer.py`（144KB 单体） | **`bff/lib/algorithms/`**（stock/dish/inventory/ops/pos/execute/util/registry） | 按域拆分、纯函数、可单测 |
| 云端 BFF | Node `bff/server.js` | 不变，扩展为 `bff/routes/`（16 个路由文件） | 算法上提后 BFF 直接承载算法 |
| 店内前端 | 单文件 HTML | `apps/admin-web`（React + TS + antd + Vite） | 原 HTML 归档 `old/apps/boss-app` |
| 双端 App | KMP + SwiftUI + Compose | 不变：`kmp-shared/` + `apps/ios-app`（源码，无工程） + `apps/android-app` | — |
| AI 视觉 | Kimi/Moonshot 经 BFF | 不变：`bff/routes/kimi.js`（6 用例 + 降级） | 已达成 |
| Python | 主力 | **仅作平价测试基准**，归档 `old/store-inventory-legacy/` | 不再参与运行 |

## 5. 替换 §10 CI/CD（现状与缺口）

| 阶段 | v1.0 承诺 | 现状 | 缺口 |
|---|---|---|---|
| Lint | SwiftLint/ktlint/detekt/ESLint | **无** | ❌ 需补 |

## 6. 替换 §6 Sprint（重排建议）

v1.0 的 Sprint 0–7 已按旧架构排布，不再适用。建议按**三条主链路**重排（先深度后广度）：

| 优先级 | 主链路 | 判据（可证伪） |
|---|---|---|
| P0 | 快照推送 → 简报 → 首页 | `pusher.js` 推得动；`/api/report/daily` 有真实数据；admin-web 首页非 mock |
| P0 | 厨房工单 → 品控 | 工单按开餐时间倒排；品控写入 `qc_records`；端到端可复跑脚本 |
| P1 | 确认台 → 队列 → 落库 → 回写 | 一条动作走完全链路；rev 冲突有处理；有自动化回归 |
| P2 | 12 模块补齐（先 Android 后 admin-web） | 逐模块 ✅/🟡/⬜ 清单，见映射表 §5.2 |
| P3 | iOS 工程化 | 补 `.xcodeproj` 并编译通过，或明确降级为源码储备 |

> 原则：**一条跑通的主链路 > 12 个半完成模块**。
