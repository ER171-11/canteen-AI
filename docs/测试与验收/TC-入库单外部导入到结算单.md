# 技术用例：入库单「外部导入」→ 生成结算单（新手可独立执行版）

| 项 | 内容 |
| --- | --- |
| 用例编号 | TC-RECV-IMP-SETTLE-01 |
| 对应功能 | FP-RECV-02 批量导入进货单 → FP-RECV-04 单张结算单 → FP-RECV-05 批量结算单 |
| 涉及页面 | 进销存 → 入库单（`/inventory/inbound`）；平台 → 系统配置（`/platform/system`） |
| 涉及账号 | 老板 `boss`（推荐）；店长 `manager` 亦可（二者 `can_write=true`） |
| 前置数据 | 无硬性要求：原料档案里没有的原料会自动建档为「待完善」草稿，不阻断导入 |
| 建议时长 | 首次执行 15~20 分钟（含准备文件） |
| 执行人要求 | 会用鼠标双击、会在输入框里打字即可；不需要懂 Excel 函数、不需要懂命令行 |
| 本用例覆盖 | 正常导入（单张 / 拆多张）、确认入库、单张结算单、批量结算单、4 种输出、7 个负向场景 |

> 一句话说明这条链路在干什么：
> **把供应商给你的那张 Excel/送货单，整批读进系统变成「进货单（JH 单）」，再把它打印成一张「结算单（JS 单）」交给老板签字、财务付款。**
> 全程你不用一个字一个字敲原料和金额，也不用做任何设置。

> 1. **别点窗口右上角的「×」**——那是退出程序。要把它收起来就点「—」。
> 2. **别在弹窗里点「取消」**——刚才选的预览就白做了（已导入成功的单据不会因此消失）。
> 3. **别把同一个文件导入两次**——系统不去重，会多出一张重复单据（多出来的可以「作废」）。

## 1. 名词对照（界面上出现的字，和它实际是什么意思）

| 界面上的字 | 实际是什么 | 大白话 |
| --- | --- | --- |
| 进货入库（JH 进货单） | 收货台账 | 供应商送货来，记一笔"收了多少货、欠他多少钱" |
| 批量导入 | 把外部 Excel/CSV 一次读进系统 | 不用一个字一个字敲 |
| 待审核（黄色标签） | 单据已登记、还没记账 | 纸写好了，账本还没改；**此时已能打结算单** |
| 确认入库（行内按钮） | 把单据推进为「已入库」 | 账本正式记上：库存增加、欠供应商增加 |
| 结算单（JS- 开头） | 付款审批单（可导出 PDF） | 打给老板签字、财务照着付款的纸 |
| 导出 PDF（微信可传） | 生成一个 PDF 文件 | 微信直接发给老板/供应商，手机上能看 |
| 新增原料（橙色标签） | 系统里原来没有这个原料 | 系统会自动建一条「待完善」草稿，不挡你导入 |

**单据编号规律**（后面核对时用得上）：

- 进货单：`JH` + 日期（8 位）+ `-` + 当天第几张，例：`JH20261030-01`
- 结算单：`JS-` + 进货单号，例：`JS-JH20261030-01`

## 4. 主流程逐步操作（TC-01）

> 每一步都写了 **「点哪里」→「看到什么」→「不对怎么办」**。
> 建议边做边截图，命名 `TC01-01.png`、`TC01-02.png`…… 后面填第 9 节的记录表要用。

### 步骤 1：启动程序

| 项 | 说明 |
| --- | --- |
| 点哪里 | 桌面上的「熊猫五福餐厅管理后台」图标，**双击**（鼠标左键快速点两下） |
| 看到什么 | 先可能什么都不发生 1~3 秒，然后出现一个白色窗口，标题栏写「熊猫五福餐厅 · 管理后台」 |
| 再等 | 窗口中间可能先是一片空白或转圈，**最多等 15 秒**，会自动出现登录页 |
| 不对怎么办 | ① 双击后 30 秒还没窗口 → 看屏幕最下面任务栏有没有新图标，点它一下<br>② 弹出「启动失败」红框 → 说明后台服务没起来，把窗口全部关掉（点 × 或任务栏右键→关闭），重新双击图标；仍不行找技术人员<br>③ 提示"端口被占用" → 同样全部关闭后重开<br>④ 窗口跑到屏幕外面了 → 鼠标点任务栏图标，按 `Win + ↑` 让它最大化 |

**窗口按钮速查（这就是"找不到最小化"的地方）**：

```
┌──────────────────────────────────────────────────────────┐
│  熊猫五福餐厅 · 管理后台                     —    □    ×  │   ← 右上角这三个小图标
└──────────────────────────────────────────────────────────┘
                                                ↑    ↑    ↑
                                     最小化 ────┘    │    └──── 关闭（退出程序）
                                      收进任务栏     └───────── 最大化 / 还原

窗口最大化时，这三个按钮在「屏幕最右上角」，不在标题文字旁边。
```

- 「—」= 收起来，程序还在，任务栏点一下就能回来 → **想"先干别的"就点这个**
- 「□」= 放大 / 变回原来大小（按钮形状会变）
- 「×」= 关掉程序（会连后台服务一起停）

| --- | --- |

| 再点哪里 | 展开后点「**入库单**」 |

| 项 | 说明 |
| --- | --- |
| 点哪里 | 右上角「**批量导入**」（不是「新建进货单」，不是「批量结算单」） |
| 看到什么 | 屏幕中间弹出白框，标题「**批量导入进货单**」，右上角有 ×，框内有蓝色「选择文件」按钮、灰色「下载导入模板」按钮，下面是一段浅蓝色说明（支持格式 / 必填列 / 不支持 .xls） |
| 还没选文件时 | 中间显示灰字「先选一个文件：会先出预览，确认后才会入队（预览不改动任何数据）」 |
| 不对怎么办 | 按钮是灰的 → ① 账号无写权限（换老板）② 页面是 Mock 状态（见上一步）。按钮点了没反应 → 等 2 秒，或按一次 `Esc` 关掉弹窗后重开 |

> 这一步只是打开窗口，**还没有碰任何数据**。可以放心反复开关。

### 步骤 5：选文件

| 项 | 说明 |
| --- | --- |
| 点哪里 | 蓝色「**选择文件**」 |
| 看到什么 | 弹出 Windows 的「打开」文件选择小窗（不是系统的资源管理器大窗口） |
| 怎么找文件 | 左侧点「**桌面**」→ 在右边列表里找到你的文件 → **双击**（或单击选中再点右下「打开」） |
| 支持哪些文件 | `.xlsx`（Excel 2007 以后）/ `.csv` / `.tsv` / `.json` / `.html`（供应商系统导出的"假 .xls"网页表格） |
| 不支持 | **旧版 .xls（Excel 97-2003）** —— 会直接报错，见 6.1 |
| 选完等一会 | 1~3 秒后窗口里出现预览（大文件可能 5 秒），同时右上角绿色提示「已预览：1 张单据 / 3 行」 |
| 不对怎么办 | 双击文件后没反应 → 看弹窗里有没有红字；红字内容见第 6 节对照表。文件在"下载"里找不到 → 文件选择窗左侧点「下载」 |

> 文件选择窗里如果看不到 .csv 文件，是因为筛选器只显示上表这些后缀；点右下角把"文件类型"改成「所有文件」即可看见（但不要选 .xls）。

### 步骤 6：检查预览（**最关键的一步，别急着点确认**）

预览区从上到下依次是：

1. 一排彩色小标签：`识别格式：csv` · `单据 1 张` · `明细 3 行` · `合计应付 ¥92.50`
2. 可能出现的黄色标签：`无效行剔除 N 行`（数量/单价不是数字）、`实收数为「×/未收」跳过 N 行`（供应商写明没送货）、`新增原料 N 种`
3. 可能出现的黄色提示框：列出"系统里没有的原料名"，并说明会自动建档为「待完善」草稿
4. **因为只有 1 张单据**，会多出三个可改的输入框：`供应商`、`单据日期`、`备注 / 单据号`
5. 明细表：`原料 / 订购量 / 单价 / 金额` 四列
6. 一个勾选框：「按应付全额登记付款（默认挂账，可后续补付）」
7. 最下面黄色提示框（说明提交后进审批、确认后重算库存与欠款）

**逐项核对清单（必须全对才继续）**：

- [ ] 「识别格式」是 `csv`（或 `xlsx`，取决于你的文件）
- [ ] 「单据 1 张」「明细 3 行」
- [ ] 「合计应付 ¥92.50」
- [ ] 明细表 3 行，单价分别是 8.10 / 2.50 / 3.20，金额 40.50 / 20.00 / 32.00
- [ ] 供应商框显示「海南菜篮子实业有限公司」（若显示空白或"未指定供应商"→ 手动输入）
- [ ] 单据日期是 `2026-10-30`（若不对，点日期框重新选）
- [ ] **勾选框保持不勾**（本单还没付款；勾了就会变成"已付清"，结算单上已付=92.50、欠款=0）

**如果出现「新增原料 N 种」**：正常，继续。导入完成后到「原料档案 → 待完善」补分类、单位，再点「确认转正」（另一个用例的事，不影响本用例结论）。

**如果金额不对**：不要点确认 → 点右下「取消」→ 打开原文件检查单价列是否有多余文字（如"8.10元/瓶"里的"元/瓶"能识别，但"壹拾"这类中文数字不行）→ 改好另存后重新导入。

### 步骤 7：确认导入

| 项 | 说明 |
| --- | --- |
| 点哪里 | 弹窗**右下角**蓝色按钮，文字是「**确认导入 1 张**」（张数会跟着变） |
| 看到什么 | 按钮转圈 1~2 秒 → 弹窗自动关闭 → 屏幕上方绿色提示：**「已登记 1 张「待审核」进货单 → 可在列表打印结算单；确认入库后库存/应付才变化」** |
| 这一瞬间发生了什么 | 系统里多了 1 张 `JH…-01` 单据，状态「待审核」：**能打结算单，但库存和欠款还没动**。这是一条安全设计 |
| 不对怎么办 | 提示变成橙色「已提交，但确认未通过 → 请到审批中心确认后，单据才会出现在列表」→ 说明动作被拦下，去左侧「平台 → 审批中心」看驳回原因（一般是权限/数据校验）。列表里没有新单 → 按 `F5` 刷新页面再看 |

> 提示条 3 秒后会自动消失，**错过了不要紧**，直接看列表第一行。

### 步骤 8：在列表里找到这张单据

| 项 | 说明 |
| --- | --- |
| 看哪里 | 大表格的**最上面一行**（列表按日期倒序，今天的单排最前） |
| 逐列核对 | 单号 `JH<今天>-01` ｜ 日期 `2026-10-30` ｜ 状态 **黄色「待审核」** ｜ 供应商 海南菜篮子实业有限公司 ｜ 明细（单元格里是「原料 数量 × ¥单价 = ¥金额」，用「；」分隔，例如 `东古一品鲜500ml 5 × ¥8.1 = ¥40.5；土豆 8 × ¥2.5 = ¥20；大白菜 10 × ¥3.2 = ¥32`；太长会被省略号截断，鼠标停上去可看全） ｜ 应付 `¥92.5` ｜ 实付 `¥0` ｜ 欠款 `—` ｜ 结算 **黄色「待入库」** |
| 顶部多了一条提示 | 蓝色提示条「待审核 1 张 · ¥92.5：单据已登记、可打印结算单，但未计入库存与应付；点行内「确认入库」后才生效」 |

| 不对怎么办 | 列表里找不到 → ① 看供应商筛选是不是选了别家（下拉点第一个「全部供应商」）② 按 F5 ③ 确认第 7 步是绿色提示而不是红色报错 |

### 步骤 9（推荐）：确认入库

> 为什么建议做：不确认入库，结算单上会**多出一行红字**「本单为待审核凭证：本单金额 ¥92.50 尚未计入系统应付…」。
> 这张纸是拿去付款的，多这行字会让财务犹豫。**真实业务里货已到，本就应该确认入库。**

| 项 | 说明 |
| --- | --- |
| 点哪里 | 这一行最右边「操作」列里的「**确认入库**」 |

## 6. 负向用例（故意做错，检查系统是否"说人话"）

> 这几条是用来验证"系统不会静默丢数据"的。每条都在**弹窗里看到红字**为止，然后点「取消」退出，**不要点确认导入**。

### 6.1 TC-02：导入旧版 `.xls`

| 项 | 说明 |
| --- | --- |
| 怎么造 | 用 Excel 新建一个表填两行数据 → 另存为 → 文件类型选「Excel 97-2003 工作簿 (*.xls)」 |
| 操作 | 按步骤 4~5 选择这个 .xls 文件 |
| 期望 | 红色提示：**「暂不支持旧版二进制 .xls（Excel 97-2003）：请在 Excel 中「另存为 .xlsx 或 CSV」后再导入（供应商系统导出的「伪 .xls」网页表格已支持，可直接导入）」**，弹窗内不出现预览 |
| 自救办法 | 用 Excel 打开 → 左上「文件」→「另存为」→ 保存类型选「**Excel 工作簿 (*.xlsx)**」或「**CSV UTF-8(逗号分隔)(*.csv)**」→ 保存 → 重新导入 |
| 判定 | 出现上述红字、程序不卡死、单据数量不变 |

### 6.2 TC-03：表头认不出来（列名古怪）

| 项 | 说明 |
| --- | --- |
| 怎么造 | 做一个 CSV，表头写成 `货名,件数,金额`（都不是系统认识的别名） |
| 期望 | 红字 **「未识别到进货单表头。需含「品名/原料名称」+「数量(或实收数/下单数)」+「单价」三列…；也可点「手动指定列」自行对应」**，且弹窗**自动展开黄色的「手动指定列」面板**（上半部分显示原始表格前 25 行） |
| 接着做 | ① 在原始表格里点一行作为"表头行"（该行变浅黄底）<br>② 下面每个字段右侧的下拉框，把「品名/原料名称」选到 `货名（第1列）`、「数量」选到 `件数（第2列）`、「单价」选到…（本例表头没有单价，需先在文件里加一列）<br>③ 点「**按此重新解析**」 |
| 期望 | 重新出现正常预览 |
| 判定 | 手动指定能救回来；不补救时给的是明确指路，而不是"解析失败"四个字 |

### 6.3 TC-04：数量列有文字（数据错误必须暴露）

| 项 | 说明 |
| --- | --- |
| 怎么造 | 把某一行"数量"写成 `五` 或 `约8` |
| 期望 | 该行被剔除，预览区出现红色标签 **`无效行剔除 1 行`**；若整份文件都不合法 → 红字 **「已识别到表头，但没有解析出有效明细行（请检查数量、单价是否为数字）」** |
| 判定 | 有明确计数/提示，**不会静默少一行** |

### 6.4 TC-05：供应商写明"未送货"

| 项 | 说明 |
| --- | --- |
| 怎么造 | 文件里加一列 **`实收数`**，其中一行填 `×`（或 `未收` / `缺货` / `已划掉`） |
| 期望 | 该行被跳过，预览区出现橙色标签 **`实收数为「×/未收」跳过 N 行`**，且**不算作错误**（不计入"无效行"） |
| 判定 | 与"数据错误"区分开，业务原因与脏数据不混为一谈 |

### 6.5 TC-06：单价为 0 或为空

| 项 | 说明 |
| --- | --- |
| 怎么造 | 一行单价写 `0`；另一行单价留空 |
| 期望 | 单价 0 的行**允许导入**（赠送/搭赠场景），金额 0.00；单价空的行被计入"无效行剔除" |

### 6.6 TC-07：同一个文件导入两次（去重提示缺失，属已知风险）

| 项 | 说明 |
| --- | --- |

## 8. 技术侧核验（执行人是开发/测试时做，非新手必做）

1. **快照核对**：`GET /api/snapshot/latest`（需带登录 token；可在 F12 → Network 里对任一 `/api/*` 请求右键「Copy as cURL」后复用）→ `data.recv` 末尾应出现本文档单据：
   - `no = JH<YYYYMMDD>-01`、`status = 待审核`、`supplier = 海南菜篮子实业有限公司`、`payable = 92.5`
   - `lines[]` 3 条，`qty × price` 与 `amount` 一致
   - 确认入库后同一单变成 `status = 已入库`（口径见 `bff/lib/recv_status.js`）
2. **审批链路**：「平台 → 审批中心」应能看到 `recv.import`（批量导入 1 张）与 `recv.post`（确认入库）两条已确认记录，操作人、时间、`source = admin-web/inventory/inbound` 齐全。
3. **预览零写**：在导入弹窗里反复「预览」→ 取消，对比 `GET /api/snapshot/latest` 的 `rev` 与 `data` 均不变（解析层 `bff/lib/recv_import.js` 纯计算）。
4. **结算单不落库**：导出 PDF/HTML/CSV 前后 `rev` 不变（结算单是只读输出层，`pages/inventory/settle/*` 无写请求）。
5. **前端无报错**：`F12` → Console 全程无红色错误；Network 里 `POST /api/inventory/recv/import/preview` 返回 200，`POST /api/actions` 返回 `confirmed: true`。
6. **金额口径**：结算单「小写合计 / 人民币大写」取**应付全额**（`payable`），同时附列 已付/欠款（`pages/inventory/settle/data.ts::buildSettleData`）。

## 附录 A：可直接导入的样例文件

本目录下已提供：`样例数据/入库单导入样例_单供应商_20261030.csv`

用法：拷到桌面 → 步骤 5 时选择它即可。内容即 3.1 节的三行数据（UTF-8 BOM，Excel 双击不乱码）。

想自己造文件，最稳的做法：
1. 点「下载导入模板」→ 得到 `进货单批量导入模板_<今天>.csv`（列：供应商 / 日期 / 原料名称 / 数量 / 单价 / 备注）
2. 用 Excel 打开 → 删掉示例行 → 按列填 → **另存为 → CSV UTF-8**
3. 回到系统导入
