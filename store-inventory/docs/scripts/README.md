# 脚本说明

## seedDB() — 真实数据基线初始化

- **用途**: 初始化全部业务数据为真实数据基线（74种原料 + 86道菜 + 1单84行采购）
- **执行条件**: 浏览器打开 HTML 时若 localStorage 无 `panda_inv_v2` 则自动执行；或在设置页点击「重置为真实数据基线」手动触发
- **依赖环境**: 浏览器(localStorage 可用)
- **是否写入数据**: 是，写入 localStorage
- **是否覆盖现有数据**: 是，手动触发时会覆盖全部业务数据
- **当前状态**: 正常
- **数据来源**:
  - 原料目录: 采购单整理_熊猫五福.xlsx（海南菜篮子实业 2026-09-12 实收84行，去重74种）
  - 菜品目录: 熊猫五福餐厅菜品保本测算.html（86道）
  - 采购单: 同 Excel 配送单 BFXYVa2609100003
- **风险**: 执行后所有手工录入的销售单/报价/配方将丢失，执行前请先导出 JSON 备份
- **回档方式**: 导入之前导出的 JSON 备份

## rebuildStock() — 库存重放

- **用途**: 按业务日期顺序重放「期初→采购→调整→销售」生成当前库存与均价
- **执行条件**: 任何单据新增/修改/删除后自动调用；init() 时调用
- **依赖环境**: 浏览器
- **是否写入数据**: 是，重写 DB.logs 和 DB.ings 的 stock/avg
- **是否覆盖现有数据**: 是，覆盖 logs 和库存计算字段
- **当前状态**: 正常（受保护逻辑，禁止直接修改）
- **回档方式**: 重新执行 seedDB() 或导入备份

## fetch_quotes.py — 一键比价抓价（外部脚本，非浏览器内）

- **用途**: 读取系统导出的 `待比价任务.json`，批量调用第三方聚合接口（onebound）的 1688 `item_search`，抓取各原料最低批发价，产出 `比价结果.json`（供系统「导入比价结果」）+ `比价结果.xlsx`（人看的比价表）
- **所在位置**: `比价脚本/`（Python 3，项目外部脚本，不参与网页运行）
- **执行条件**: 手动执行。Windows 双击 `比价脚本/运行比价.bat`；或命令行 `python fetch_quotes.py`
  - 支持 `--task <任务文件>` / `--limit N`（试跑）/ `--dry-run`（免密钥验证流程）/ `--out <目录>`
- **依赖环境**: Python 3 + `requests`；Excel 导出需 `openpyxl`（`pandas` 为可选分析依赖）；需在 `比价脚本/config.json` 填入 onebound 的 `api_key`/`api_secret`
- **是否写入数据**: **不直接写系统数据**。只产出结果文件，由用户在网页里点「导入比价结果」才写入 `DB.quotes`
- **是否覆盖现有数据**: 否。导入为追加 + 去重（按「原料+来源+价格」），不删除/覆盖任何既有报价
- **请求限频**: 每次请求间隔 `sleep`（默认 1.5s），失败按指数退避重试 `retry`（默认 2）次；`page_size`/`pages`/`top_n` 可配
- **当前状态**: 正常（已用 `--dry-run` 完成全流程验证：任务解析、跳过 conv≠1、JSON 契约、Excel 公式）
- **风险**:
  - `config.json` 含 API 密钥，**禁止外发/提交到公开仓库**
  - 1688 报价可能不含运费/不含税、规格与采购单位不一致，导入前须人工核对 Excel 的「商品标题」列
  - 换算率 ≠ 1 的原料默认跳过，避免错价
- **数据来源**: 1688 商品搜索（经 onebound 聚合接口），关键词来自系统任务清单（已自动净化）
- **回档方式**: 导出前先做 JSON 备份；误导入后在「外接比价 → 报价记录」逐条删除，或用备份在设置页「导入JSON备份」整体回滚

## fetch_quotes_selenium.py — 一键比价抓价 · 浏览器引擎（2026-09-13 新增）

- **用途**: 与 `fetch_quotes.py` 完全相同（读 `待比价任务.json` → 产出 `比价结果.json` + `比价结果.xlsx`），但改用 **Selenium 驱动真实 Chrome/Edge** 打开 `s.1688.com` 搜索结果抓价。适用于 1688 开放平台接口不可用/额度不足/数据不符合预期的场景
- **所在位置**: `比价脚本/`（Python 3，外部脚本，不参与网页运行）
- **共用逻辑**: 直接 `import fetch_quotes` 复用 `find_task_file`/`load_task`/`write_json`/`write_excel`，**任务/结果 JSON 契约与接口引擎完全一致**，前端无需区分
- **执行条件**: 手动执行。Windows 双击 `比价脚本/运行比价-网页版.bat`；或命令行
  - `python fetch_quotes_selenium.py`（全量）
  - `--limit 3` 先试跑 / `--keyword 东古一品鲜` 单关键词调试 / `--dry-run` 不开浏览器验证链路
  - `--delay 2.5`（默认节奏，秒）/ `--top-n 3` / `--pages 1`
  - `--browser edge`（本机无 Chrome 时用 Edge）/ `--binary <exe路径>` / `--headless`（1688 易拦截，不推荐）
- **依赖环境**: Python 3 + `selenium`（+ `webdriver-manager` 兜底）；本机需有 Chrome 或 Edge；Excel 导出需 `openpyxl`
- **登录态**: 独立用户目录 `比价脚本/chrome_profile/`，**首次运行需人工扫码登录 1688**，之后长期免登录；未登录时脚本会暂停并轮询等待
- **节奏控制**: 每次浏览器操作间隔默认 **2.5s**（`delay`/`jitter` 可配）；每页下滑 3 次触发懒加载；每 10 个原料落一次中间结果
- **是否写入数据**: **不直接写系统数据**。只产出结果文件，由用户在网页里点「导入比价结果」才写入 `DB.quotes`
- **是否覆盖现有数据**: 否。导入为追加 + 去重（按「原料+来源+价格」）
- **当前状态**: 正常（已用 `--dry-run` 验证任务解析/跳过 conv≠1/JSON 契约/Excel 公式；已用 Edge 无头验证浏览器启动链路）
- **风险**:
  - `chrome_profile/` 含个人 1688 登录凭据，**禁止外发/提交仓库**
  - `s.1688.com` 前端改版会使选择器失效（日志会打印命中的选择器；修 `CARD_SEL`/`TITLE_SEL`/`PRICE_SEL` 常量即可）
  - 遇滑块/登录验证必须人工处理，**禁止**自动化绕过；**禁止**把 `delay` 降到 1s 以下
  - 抓到的价格同样存在「不含运费/不含税/规格口径不一」问题，导入前须人工核对
- **数据来源**: `s.1688.com/selloffer/offer_search.htm?keywords=<关键词>`，关键词来自系统任务清单
- **回档方式**: 删除 `fetch_quotes_selenium.py` / `运行比价-网页版.bat` / `chrome_profile/` / `debug/`；已导入报价在「外接比价 → 报价记录」逐条删除

## make_quote_list.py — 待比价任务 → 1688 清单询价材料（2026-09-13 新增）

- **用途**: 把 `待比价任务.json` 转成 1688 买家工作台「询报价 → 清单询价」可上传的 Excel 模板，另附 Markdown 说明文档；用于人工询价兜底（不抓价）
- **执行条件**: 手动执行 `python make_quote_list.py`（自动找最新任务文件）；可选 `--task <路径>` / `--out <目录>`
- **输出**: 项目根目录 `询价清单/询价清单_YYYY-MM-DD.xlsx`（工作表：全部汇总 / 按类目分表 / 使用说明）+ `询价清单说明_YYYY-MM-DD.md`
- **Excel 特性**: 「采购数量」列留空待填（正整数校验）、「期望单价上限」可选、表头深底白字、冻结首行、自动筛选、列宽自适应
- **是否写入数据**: **否**，只产出文件，不碰 `DB`。询价结果仍需回系统手工「录入报价」或用抓价脚本导入
- **依赖环境**: Python 3 + `openpyxl`
- **当前状态**: 正常（已用 74 项任务验证：4 个类目 57/13/3/1 分表，6 个工作表结构校验通过）

## 批量导入 — importPo*() / importRec*()（前端，2026-09-13 新增）

- **用途**: 「进货入库」批量导入进货单（`parsePoInput → previewPoImport → commitRecvImport`）；「菜品配方」批量导入食谱卡（`parseRecInput → previewRecImport → commitRecImport`）
- **执行条件**: 对应页工具条按钮 / 文件选择框手动触发；支持 `.csv` 与 `.json`，不支持 `.xlsx` 直传（需另存为 CSV）
- **依赖环境**: 浏览器（`FileReader` + `TextDecoder`，无外部库）
- **是否写入数据**:
  - 预览阶段：**不写入**
  - 确认后：进货单写 `DB.recv`（+ 可能新增 `DB.ings`/`DB.suppliers`）并调用 `rebuildStock()`；食谱卡写 `DB.rec`（+ 可能新增 `DB.dishes`/`DB.ings`）
- **是否覆盖现有数据**: 否。采购单为追加；食谱卡同名菜默认覆盖其配方（可取消勾选改为合并），原料/菜品一律按名称精确匹配后追加
- **新原料策略**: 未匹配到名称的原料由 `createIngFromImport()` 新建（`stock/avg=0`，单位默认「斤」，分类默认「其他」），保证食谱卡中的新原料出现在原料库存
- **CSV 列**:
  - 采购单: `供应商 / 日期 / 原料名称 / 数量 / 单价 / 备注`
  - 食谱卡: `菜品名称 / 菜品分类 / 原料名称 / 净料用量 / 库存单位 / 原料分类`
- **当前状态**: 正常（`parseCsv/csvMap/normDate/numOr` 已用含引号逗号、CRLF、斜杠日期、缺列检测的用例验证）
- **风险**: 导入模型误判会导致新原料以默认单位/分类入库，导入后请在「原料库存」核对单位与分类；CSV 编码按 UTF-8 优先、出现替换符时回退 GBK
- **回档方式**: 在「进货入库」删除导入的进货单（台账自动重算）；配方可重新编辑或用设置页「导入JSON备份」整体回滚
