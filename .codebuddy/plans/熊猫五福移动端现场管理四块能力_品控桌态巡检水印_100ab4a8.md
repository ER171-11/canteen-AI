# 餐厅现场管理四块能力（A/B/C/D）实施计划（精简版）

## 目标

四块相互独立、可单独上线验收：A AI 品控识别；B 前厅桌态；C 巡检节点拍照；D 水印相机。admin-web 补管理侧三页。

## 硬约束（已与用户确认）

- 品控照片 → 外部对象存储（OSS/S3/MinIO），DB 只存状态 + URL 引用；未配置时降级「图片不可用」，功能不中断。
- 巡检照片 → 仅手机本地，服务器只存状态/元数据，不收图。
- 50 个标准节点 = BFF 内置主数据，App 只读，本轮不做配置界面。
- 后端零依赖红线：仅 Node 内置模块 + 手写 SigV4；图片不经 BFF 落盘/入库；不引 SDK；不得硬编码密钥。

## 关键技术决策

- **品控流**：拍照 → 客户端水印 → `/api/kimi/vision?type=qc`（内存识别）→ 预签名直传 OSS → `POST /api/actions` 入队 `qc.record` → 不合格锁定工单 + 经 SSE 推 admin-web 待办。
- **巡检流**：读 50 节点主数据 → 拍照存本地 → 仅上报（节点+责任人+时间+是否拍照）状态 → `/api/modules/inspection` 聚合看板。
- **相机**：系统 `TakePicture()` + FileProvider 写原图到私有目录 + Canvas 合成水印，零新增依赖；原图压缩长边 ~1600px / JPEG 80。
- **共享层**：kmp-shared 统一 DTO/Repository/ViewModel；admin-web 另写 DTO（无 JS target）。
- **写操作红线**：所有业务写必须经 `redline.ConfirmGateway`，不得 UI 直调 ActionRepository。
