# AI协作协议 (AI Agent Protocol)

> 本文件定义了AI在本项目中的行为规范。AI在执行任何任务前，必须读取并遵循本协议。

## 1. 标准交互工作流

收到任务后，AI必须按以下顺序执行：

1. **查阅地图**: 读取 ARCHITECTURE.md 获取全局视角，定位问题所属模块。
2. **查阅历史**: 查阅 CHANGELOG.md 确认相关模块的历史变更与废弃项。
3. **查阅模块文档**: 读取对应 modules/[模块名].md，了解边界和约束。
4. **判断是否高风险**: 若涉及核心业务逻辑(计价/配方/库存重放)/种子数据脚本/大范围重构/文件删除重命名，则进入步骤5。否则跳到步骤6。
5. **输出修改计划**: 输出 [EDIT_PLAN] 格式，等待人工确认后方可执行。
6. **执行修改**: 遵循现有架构规范执行代码修改。
7. **运行校验**: 浏览器打开 HTML 检查各 tab 是否正常，有无控制台报错。
8. **输出对账**: 输出 [WORK_DIFF] 格式，列出变更详情。
9. **更新文档**: 同步更新 CHANGELOG.md 和对应模块文档。

## 2. 强制输出格式

### [EDIT_PLAN] 修改计划格式
在修改核心文件前，必须按以下格式输出：

```
[EDIT_PLAN]
- 目标文件: [列出将要变更的文件路径]
- 变更摘要: [简述将要执行的修改]
- 风险评估: [说明该修改可能带来的副作用]
- 是否影响其他模块: [是/否，说明影响范围]
- 是否需要人工确认: [是/否]
```

### [WORK_DIFF] 工作差异对账格式
在每批工作完成后，必须按以下格式输出：

```
[WORK_DIFF]
- 已实现功能: [列出本次完成的任务]
- 修改文件: [列出实际变更的文件路径]
- 设计意图匹配度: [说明代码如何体现架构设计]
- 偏离或简化说明: [如有未完全按架构文档执行的地方，必须说明理由]
- 未处理项: [列出未完成的部分]
- 风险点: [列出潜在风险]
- 是否需要更新文档: [是/否]
```

## 3. 高风险操作清单

以下操作必须输出 [EDIT_PLAN] 并等待人工确认：

- 修改 `rebuildStock()` 库存重放逻辑（移动加权平均计价核心）
- 修改 `dishRecipeCost()` / `calcSaleCost()` 成本核算逻辑
- 修改 `seedDB()` 种子数据脚本
- 修改 localStorage key (LS_KEY)
- 修改数据结构（DB 对象字段）
- 跨模块重构 / 目录结构调整 / 文件重命名
- 删除或重命名文件
- **删除或替换既有可用功能**（页面改版、系统替代、功能下线）——见 §7

## 4. 文档维护协议

- 代码修复或架构调整后，AI必须主动询问：「是否需要我将此次修改同步更新至 CHANGELOG.md？」
- 若确认更新，需按照 CHANGELOG.md 的标准格式追加记录，并打上准确的时间戳。
- 禁止出现"代码已改，文档未改"的长期状态。

## 5. 受保护逻辑标记

在关键代码中，开发者可加入以下标记：

```javascript
// PROTECTED: 该逻辑由开发者手动调整，AI不得直接覆盖
```

当前受保护区域：
- `rebuildStock()` 移动加权平均重放逻辑（计价核心）
- `dishRecipeCost()` 配方成本核算（毛利核心）
- `seedDB()` 真实数据基线

## 6. 真实数据基线保护

- 禁止恢复任何演示/虚构数据
- 原料目录必须来自真实采购单
- 采购单必须来自真实配送单据
- 销售单/外部报价/配方为空属正常状态（待真实业务录入）

## 7. 替代式迁移协议（以新替旧时必须遵守）

> 展开版：`docs/规范/迁移颗粒度规范.md`　基线样例：`docs/迁移基线/FP-进货入库.md`

1. **迁移单位是功能点（FP），不是页面、不是模块。** FP = 用户可见、可单独操作、可单独验证的一个动作或视图。
2. **先建基线，再动手**：从源系统源码抽取 FP 清单（每项带 `文件:行号` 证据），人工复核后放入 `docs/迁移基线/`。
   无基线不得启动迁移，更不得宣称完成。
3. **四态标注，留空即失败**：每个 FP 必须标 ⬆️已移植 / 🔄等价替代 / ⬜待补 / ⚰️废弃；
   🔄 须附 ADR 编号 + 批准人，⬜ 须附任务卡 ID，⚰️ 须附业务理由 + 批准人。
4. **两条门禁互不替代**：平价（差分）测试证明「**算得对**」，FP 清单证明「**功能齐**」。
   平价测试全绿 ≠ 功能已迁移。
5. **禁止以「页面存在 / 接口存在」充当「功能完成」**——这是功能静默丢失的主要入口。
6. **替代模式**下所有 ⬜ 一律视为**回归缺陷**并排期补齐，不得默认「留在旧系统」；
   若确为并存模式，须在 ADR 中写明并获批准。
7. 违反本节属 §3 高风险操作，必须先输出 `[EDIT_PLAN]` 等待确认。
